# Claude Code Agent

Claude Code is Anthropic's official CLI for Claude. It's one of the primary agents supported by orch.

## Prerequisites

Install Claude Code following Anthropic's documentation:

```bash
# Via npm
npm install -g @anthropic-ai/claude-code

# Verify installation
claude --version
```

## Configuration

### Basic setup

```yaml
# .orch/config.yaml
agent: claude
```

### With custom prompt

```yaml
agent: claude

claude:
  prompt_template: |
    ultrathink Please read 'ORCH_PROMPT.md' in the current directory.
    Follow the instructions carefully.
    
    {{issue}}
```

## Running with Claude

```bash
# Use default agent (if configured as claude)
orch run my-issue

# Explicitly specify claude
orch run --agent claude my-issue
```

## How orch uses Claude

When starting a run, orch:

1. Creates a tmux session
2. Changes to the worktree directory
3. Launches claude with the prompt:
   ```bash
   claude --dangerously-skip-permissions [--model <model>] [--effort <variant>] "Your prompt here..."
   ```
4. By default, uses `--dangerously-skip-permissions` for non-interactive use
5. Passes the resolved model and variant (if configured) as `--model` and `--effort`

## Agent Detection

The orch daemon detects Claude's state by monitoring terminal output:

### Running indicators
- Token counter visible
- Output actively scrolling
- Claude UI elements present

### Blocked indicators
- "↵ send" prompt visible
- "? for shortcuts" visible
- "accept edits" prompt
- "shift+tab to cycle"

### Exit indicators
- Shell prompt visible (`$`, `%`, `❯`)
- No Claude UI elements

## Prompt Best Practices

### Use ultrathink

Start prompts with `ultrathink` for thorough analysis:

```yaml
claude:
  prompt_template: |
    ultrathink Please read 'ORCH_PROMPT.md' and follow the instructions.
    {{issue}}
```

### Include ORCH_PROMPT.md reference

The `ORCH_PROMPT.md` file is auto-generated by orch with issue context:

```yaml
claude:
  prompt_template: |
    Please read 'ORCH_PROMPT.md' in the current directory.
    It contains the issue specification and instructions.
```

### Direct issue embedding

Or embed the issue directly:

```yaml
claude:
  prompt_template: |
    ## Task
    {{issue_title}}
    
    ## Details
    {{issue}}
    
    ## Instructions
    - Implement the requirements
    - Write tests
    - Create a PR when done
```

## Profiles

The claude CLI has no `--profile` flag. orch implements profiles by setting the
`CLAUDE_CONFIG_DIR` environment variable for the agent process: each entry in
`claude.profiles` binds a profile name to a config directory (a separate Claude
account/configuration).

```yaml
claude:
  # Profile selected when --profile is not given
  default_profile: work
  profiles:
    work:
      config_dir: ~/.config/claude-work
    personal:
      config_dir: ~/.claude
```

Select a profile per run with orch's `--profile` flag:

```bash
orch run --agent claude --profile work my-issue
```

Profiles can also pin execution targets (see `.orch/config.example.yaml`):

```yaml
claude:
  profiles:
    work:
      target: remote-worker            # config.targets name; omit to run locally
      allowed_targets: [remote-worker] # restrict where this profile may run
      config_dir: ~/.config/claude-work
```

## Permissions

By default, orch runs Claude with `--dangerously-skip-permissions` for automation:

```bash
claude --dangerously-skip-permissions "prompt..."
```

This allows Claude to:
- Read/write files without asking
- Execute commands without confirmation
- Make git commits and pushes

**Security note:** Only use this in trusted environments with proper git branch protection.

## Interacting with Claude

### Attach to session

```bash
orch attach my-issue
```

This opens the tmux session where Claude is running. You can:
- See Claude's work in real-time
- Type messages to Claude
- Paste images
- Provide input when Claude asks questions

### Detach

Press `Ctrl+B` then `D` to detach without stopping Claude.

### Send a message

Send input without attaching:

```bash
orch send my-issue "Please also add documentation"

orch send my-issue <<'EOF'
Please also add documentation.
Include the rollout steps in the PR body.
EOF
```

## Troubleshooting

### Claude not responding

1. Check if session exists:
   ```bash
   orch ps
   ```

2. Check daemon logs:
   ```bash
   tail -f ~/Library/Logs/orch/daemon.log   # Linux: ~/.local/state/orch/daemon.log
   ```

3. Attach and check Claude's state:
   ```bash
   orch attach my-issue
   ```

### Permission errors

orch passes `--dangerously-skip-permissions` by default. If Claude keeps asking
for permissions, check whether `claude.extra_args` is set in your config —
configured extra args replace the default flags, so include the permission flag
yourself:

```yaml
claude:
  extra_args:
    - --dangerously-skip-permissions
```

### Model selection

orch passes the resolved model and variant to the claude CLI:

```bash
claude --dangerously-skip-permissions --model claude-fable-5 --effort high "prompt..."
```

- `--model` comes from `orch run --model`, a preset `model`, or the top-level `model` config key
- `--effort` comes from `orch run --model-variant`, a preset `variant`, or the top-level `model_variant` config key (valid values: `low|medium|high|xhigh|max`)

If neither is configured, claude falls back to its own default model.

### API errors

If you see API rate limits or authentication errors:

1. Check your Anthropic API key
2. Verify billing status
3. Check Claude Code logs

## Advanced Configuration

### Extra CLI arguments

For special requirements, pass additional flags to the claude CLI. Note that
`extra_args` replaces the default flags, so include
`--dangerously-skip-permissions` yourself if you still want it:

```yaml
claude:
  extra_args:
    - --dangerously-skip-permissions
    - --add-dir
    - /path/to/shared
```

### Working with the Claude UI

Claude has various UI modes and features. In tmux sessions:

- Scrollback: `Ctrl+B [` then use arrow keys
- Exit scroll mode: `q`
- Copy text: Select with mouse, then `Ctrl+B ]` to paste

## Status Mapping

| Claude State | orch Status |
|--------------|-------------|
| Initializing | `booting` |
| Actively working | `running` |
| Waiting for input | `waiting` |
| Completed task | `done` |
| Error message | `failed` |
| Exited to shell | `unknown` |
